## 0. 一句话结论

**这是一份"野心极大、诚实度罕见、但成熟度明显不足"的独立项目。**

它不是在做一个"记忆组件"，而是在做一套**白箱 AGI 运行时**——长期记忆只是其中最成熟的一层。它的核心差异点是真实存在的：**记忆真源是纯 md 文档（不是向量库）**、**写入与检索裁决零 LLM 参与（确定性规则）**、**全过程可审计可复现**。这三点在同类里确实少见。

但它的"领先"目前**只体现在设计取向，不体现在被独立验证的效果**。README 里的横评数字来自作者自建的基准仓（同作者、1 star），且仓库内已有外部审计指出该基准存在"查询与索引同源"的构造性缺陷（详见 §6.1）。工程侧还有多个未修复的 P1 缺陷（含一条可硬删除记忆的越权路径）。

**结论：值得研究和试用，不适合直接作为生产环境的关键记忆底座。**

## 2. 核心功能与设计目标

### 2.1 设计目标（作者自述 + 从代码结构反推）

项目的自我定位是"**白箱 AGI 架构探索**"，记忆只是入口。仓库描述原文：

> 元认知（自我认知循环）、持续学习（知识飞轮）、世界模型（条件空间+语义时空图）、自我改进（自举纪律）、零 LLM 白箱管线与可审计信任护栏。

拆成可验证的工程目标，其实是这四条：

1. **不失忆**——记忆一旦落盘不静默淘汰；遗忘只能显式发起；检索索引只是派生物、原文即真源。
2. **无幻觉**——"记什么/取什么/能否写入"全部由确定性规则裁决，**不用 LLM 做判断**；写没写成功只看 `committed` 字段，不假装通过。
3. **可审计**——记忆本体是人类可读的 md 文档，任何编辑器可打开；全链路留痕。
4. **跨 harness**——大脑是标准 stdio MCP server，任何支持 MCP 的宿主可挂载。

### 2.2 五件套（同一仓库内的五个子系统）

| 层 | 目录 | 定位 | 你要不要关心 |
|---|---|---|---|
| 灵枢大脑 | `md_cg/` | **记忆系统本体**（元认知层） | ✅ 这就是你要用的 |
| Rust 检索引擎 | `rust/` | 只读检索内核（库内嵌 / `--serve` 多智能体 / 评测器） | ⚠️ 需 `cargo build`，仅影响性能与评测 |
| 蜂群运行时 | `swarm/` | 多进程蜂群执行层（心跳/信任聚合/健康评分） | ❌ 可不接 |
| 中文编译器 | `compiler/` | 术数编译器（词法→语法→名实校验→代码生成） | ❌ 可不接 |
| 蜂巢并发引擎 | `hive/` | worker 池调度（任务 spec 进 / result 出） | ❌ 可不接 |

**关键事实**：`md_cg/`（大脑）**零依赖其余各层**。你只想用记忆，只接大脑即可。

### 2.3 真正区别于同类的能力

这几点是它相对 mem0 / Letta / Zep 的**真实差异**：

1. **记忆真源 = 纯 md 认知图**。不是向量库、不是数据库。可直接 `git diff` 看记忆变化，可直接用编辑器改。
2. **零 LLM 写入路径**。写入耗时自报 0.011–0.019 秒（对比 OpenViking 75.7–164.7 秒、抽取式三家 304–658 秒）。这是架构差异，不是调优差异。
3. **四态资格裁决**（ACCEPT / REJECT / DEFER / BLINDSPOT）+ 三道写入闸门。不"猜"，不确定就标 BLINDSPOT。
4. **CCG 六要素记忆卡**（功能名 / 生效条件 / 子功能 / 执行 / 验证方式 / 不适用条件），且**编译者不得自证**——LLM 产出的候选必须经"认知图之外的编外单元"复核才准落库。
5. **中文优先语义层**。用中文语义归一化解决英文检索，不上向量（明确裁定）。

## 3. 运行机制与工作流程

### 3.1 架构

```
DSH / Claude Code / Codex CLI / ZCode / CodeBuddy
  Agent Loop ──┬── 工具面（cg / stg / mdcg_*）
               └── session/event（自动记忆钩子 · 自动召回注入）
                     │  stdio · 逐行 JSON-RPC
        ┌────────────▼─────────────┐
        │  灵枢大脑子进程（唯一）      │
        │  python -m md_cg.mcp_server │
        │  md 认知图 = 唯一真源       │
        └──────────────────────────┘
```

### 3.2 写入链（对话 → 落盘）

1. **触发**：DSH 的 session/event 钩子自动捕获对话轮次，或 Agent 显式调用 `cg(op=write)`。
2. **三道闸门**（必须依次穿过）：
   - `audit`（审计）
   - 一致性（consistency）
   - `gated` 三问四态（ACCEPT / REJECT / DEFER / BLINDSPOT）
3. **落盘充要条件 = 最终判定 ACCEPT**。
   - 非 ACCEPT → 进 `review_queue` 或 `rejected`（负记忆），**不落盘**。
   - 返回体形如 `{"ok": true, "committed": false, "moved_to": "review_queue"}` —— **`ok: true` 不等于写成功，只看 `committed`**。
4. **内容类型影响严格度**：
   - `content_kind: 'text'`（默认）→ 须带 CCG 六要素，缺要素即 `REJECT`。
   - `content_kind: 'code'` → AST 解析通过即 `ACCEPT`（想快速落盘用这个）。
5. **fail-closed**：策略文件不可用或形状非法时，既不落盘也不进队列，返回 `moved_to: "policy_unavailable"`。

### 3.3 召回链（提问 → 注入）

1. **触发**：新会话自动召回注入，或显式 `mdcg_recall` / `mdcg_search`。
2. **多路融合检索**：词法路（char-bigram）+ 同义扩展 + 因果路 + 时间路 → RRF 融合。
3. **四层证据防火墙**：召回前负条件路由 → 候选生成排除 → `judge_ranking` 白箱终排 → 资格标注。
4. **注入上下文**：带"不可信边界声明"（防止记忆内容被当成指令）。

### 3.4 工具面（默认只暴露 2 个）

| `tools` 模式 | 暴露数 | 说明 |
|---|---|---|
| `'core'`（**默认**） | **2** | 仅 `cg` / `stg` |
| `'brain'` | 30 | `cg`/`stg` + 28 个细粒度 |
| `'all'` | 30 | full 面 33 减去 3 个宿主级风险工具 |

`cg` 有 38 个 op、`stg` 有 5 个 op，共 43 个。风险工具（`mdcg_forget` / `mdcg_restore` / `mdcg_review_decide`）需 `can_admin`，**即使 `tools: 'all'` 也不自动暴露**。

### 3.5 关键运维约束

- **写权限默认关闭**：不配凭据即以只读 `guest` 运行——**读得到、写不进**。
- **升级后必须重启长驻 MCP 进程**：大脑是 stdio 长驻进程，模块只在首次导入时读盘；升级后新旧代模块会在同一进程混用，症状是 `ImportError`。自检：`cg(op=info)` 看 `stale_on_disk` / `restart_required`。
- **编码约定**：全仓 UTF-8（无 BOM），路径可含中文，NFC 形态不合法即**显式拒收**（不静默归一化）。

### 4.5 日常使用（真正的用法）

装完就像往常一样对话。典型交互：

| 你说 | 背后发生 |
|---|---|
| 「请记住：我们团队的发布窗口是每周三」 | Agent 显式归档 → `cg(op=write)` 过三道闸门 → 节点落盘 |
| （新开会话）「我们的发布窗口是哪天？」 | 自动召回注入 → `mdcg_recall` 命中并带入回答 |
| 「把上次定的接口约定讲一遍」 | `cg(op=route)` 条件路由 + `stg(op=timeline)` 时间线回溯 |

**排障入口（很有用）**：`~/.dsh/logs/dsh-memory-hook-audit.json`——有界落盘审计，记录哪些消息被设计滤除（`filtered`）、写入/跳过（`skipped`）计数。"对话里明明说了、记忆里却没有"时先看它。

### 4.6 其它 harness

`md_cg/` 是标准 stdio MCP server，Claude Code / Codex CLI / ZCode / CodeBuddy 都能挂：

| 宿主 | 纪律注入方式 |
|---|---|
| DSH | `cordis.patch.yml` 的 `personaPrefix`（compact · 每轮） |
| CodeBuddy | 项目根 `CODEBUDDY.md`（full · 会话起始） |
| ZCode / Codex CLI | 项目根 `AGENTS.md`（full · 会话起始） |
| Claude Code | 项目根 `CLAUDE.md`（full · 会话起始） |

⚠️ **重要差异**：**自动记忆钩子 + 自动召回注入是 DSH 插件层的功能**（走 session/event）。在其它宿主上你拿到的是"大脑 + 纪律注入"，**自动沉淀体验会明显打折**。README 里"装完即可对话"的顺滑感是 DSH 专属的。

**我的判断**：
- 如果你的目标是**"给 DSH 加一个可审计的长期记忆"** → 灵枢是当前 DSH 生态里的合理首选，但要做好"用之前先读 42 个 issue"的心理准备。
- 如果你的目标是**"找一个稳定的生产级记忆底座"** → 用 mem0 或 Graphiti，灵枢作为研究与对照对象。
- **不建议**把它当作唯一记忆底座——它的开放 issue 里有可导致**记忆永久丢失**的路径（见 §6.2）。

## 6. 你可能尚未考虑到的问题（重点）

这一节是本次分析中**信息价值最高**的部分。以下全部有据可查。

### 6.1 ⚠️ 最重要：核心基准存在"查询与索引同源"缺陷

**Issue #124**（外部用户 `level0000x` 提交，仍开放）：

- 主公开基准 `locomo-zh-500` 的每道题查询串由该题 gold 文档的 `zh_fields.terms` 派生；
- 而**同一份 `terms` 又被逐字内联进被索引正文**（`词：...` 行）；
- 检索因此部分退化为"用文档自带的字段匹配这份文档"。

**实测后果**：

| | hit@1 | hit@5 |
|---|---:|---:|
| 官方公布的完整主链路 | 94.6% | 99.2% |
| **不含任何检索引擎的 20 行平凡基线** | **95.2%** | 98.6% |

消融实验：把正文里那一行 `词：` 去掉后，平凡基线从 96.6% → **72.2%**。
**即约 24 个百分点的 hit@1 由"查询词与正文同源"贡献。**

**这对你意味着什么**：
1. README 头条数字 `hit@1 94.6% / hit@10 99.2%` **目前无法区分"引擎好"与"题面与正文同源"**。
2. §5 里"六家横评"的对照结论**建立在同一构造上**——包括那些看起来对 MemOS / Mem0 很不利的数字（逐字率 40% / 33%）。
3. 项目**已主动声明**该基准的其它边界（零干扰池、只评检索不评答案），但**未声明这一条**——issue 里作者也承认这是"不同的失效机理"。

**行动建议**：把 README 的横评数字当作**作者的内部实验读数**，不要当作中立第三方结论。要用它，请自己在 `hive-memory-bench` 上重跑。

### 6.2 ⚠️ "不可遗忘"承诺有一个洞：可越权硬删除

**Issue #144**（外部用户 `cyd471` 提交，仍开放）：

- 走 `forget` → 需 admin + 自治确认 + 软删进 `trash/` + 留墓碑（安全）；
- 走 **`cg(op=verify, verdict="falsified")`** → **任何有 verify 作用域的令牌**（含默认装机的 designer 令牌）都能**立即 `os.remove` 原节点**——不进 trash、不写 `_deletions.jsonl`、`restore()` 返回 `not_in_trash`，只在 rejected 层留正文前 200 字符。

**这与 README 首页"记忆一旦落盘便不会消失""遗忘只能由显式 `cg(op=forget)` 发起"的核心承诺直接矛盾。**

同类还有：
- **#132**：密钥轮换是**无迁移路径的单向数据丢失操作**；令牌库损坏 → 常驻进程全量凭据失效。
- **#172**（P1）：`MdCGOS.restore()` 路径穿越——`node_id` 零校验直接拼路径，**先读后拦**。
- **#146**：**单个节点 frontmatter 手改坏（如漏一个 `}`）即整库打不开、MCP 服务起不来**；改坏密级行还会让他会话读到密文正文的明文。
- **#167**：开启强制对端签名后，`import`/`observe` 的 `signers_file` 参数可绕过验签。

**行动建议**：① 不要给不可信 Agent 写权限；② 定期备份 `~/.dsh/.dsh-memory/data/mdcg`（它只是 md 目录，`git init` 一下就行）；③ 不要在单节点上手改 frontmatter。

### 6.3 ⚠️ "自我改进不丧失验证资格"这个卖点目前是可绕过的

**Issue #126**（外部用户 `level0000x`）：

- `frozen.json`（冻结凭证）的唯一产出函数 `freeze()` 在**生产代码中零调用点**（只在测试里用）；
- 唯一的消费方 `scripts/interop_gate.py` **只做自洽性检查**——源码里 `frozen` / `digest` / `fingerprint` / `A3` / `judgment` 五个词全部不出现；
- **实测**：手写一份形状合法、内容全假的 `verdict.json`（指纹 `aaaa`/`bbbb`、`passed=999`）→ 门禁 `exit 0` **放行**。

> 即：**任何人都能凭一个手写 JSON 让"双实例互验"判定通过。**

### 6.4 ⚠️ 默认性能面与"高性能"宣称不符

**Issue #149**：仓库内**已实现且实测有效**的四套加速结构，**默认全部关闭**：

| 加速器 | 实测效果 | 默认 |
|---|---|---|
| 热路径 query 缓存 | 12 ms → **0.04 ms（300×）** | ❌ 关 |
| 索引化 BM25 路 | 单查询读盘 **567 → 0** | ❌ 关 |
| 倒排候选层 S7 | 窄化率实测 **0%**（无效） | ❌ 关 |
| RRF 精确候选 | 候选 −40%，但**总耗时反而变慢** | ❌ 关 |
| 读缓存 | 默认开（关掉劣化 6.2×） | ✅ 开 |

**即：开箱性能不是 README 宣传的那个性能。** 想拿到高性能要手动设 `MDCG_HOTCACHE=1` 等环境变量——而 S7 和 RRF 候选实测**未产生净收益**。

### 6.5 ⚠️ "装完即可用"在写入侧不成立

- **Issue #68**：**自动记忆节点缺 CCG 六要素 ⇒ 分桶空 / 条件路由不可用**。
  这意味着：**自动沉淀的记忆无法使用条件路由这个旗舰功能**——而条件路由正是 README 主推的卖点之一。
- **Issue #134**：CCG 六要素的四态判定**在生产语料上退化为单态**；条件空间四槽中 2 槽无默认消费方。
- 结合 §3.2 的写入闸门：`text` 类内容缺六要素直接 `REJECT`。所以"我只是聊天，它自动记下来"这条路径，产出的是**功能受限的节点**。

### 6.6 ⚠️ 检索存在结构性弱项

- **Issue #108**：**长拼接查询下召回扩展只覆盖开头**——同库同查询，**朴素 BM25 达 33.7%@10，本引擎仅 1.2%@10**。这是近 28 倍的差距，不是微调问题。
- **Issue #130**：`_path_entity` 分数恒为常量 1.0 却以全权重进融合，实测把真命中从第 26 位压到第 50 位。
- **Issue #124 衍生**：以该基准做 A/B 时约 24pp 的信号是假的 → **迭代信号失真**。
- 英文机械归一端到端 hit@10 仅 **57.6%**（自报）。

## 7. 使用建议与决策清单

### 7.1 如果你决定试用（推荐做法）

1. **先只读试跑**：不签发 token，以 `guest` 身份跑一周，看召回质量是否符合你的预期。
2. **用隔离目录做实验**：`mdcg.root` 指向一个测试目录，不要直接上生产。
3. **开 `tools: 'core'`**：先只用 `cg` / `stg`，别开 `all`。
4. **手动 git 化你的记忆库**：`cd ~/.dsh/.dsh-memory/data/mdcg && git init && git add -A && git commit -m init`——这是对抗 #144 / #146 / #132 最有效的兜底。
5. **别放敏感信息**：#69 / #164 表明密级隔离有漏。
6. **开启加速器**：`MDCG_HOTCACHE=1`（300× 收益，风险低）。
7. **订阅 issue 区**：42 个开放 issue 里 P1 的在陆续修，装之前先扫一遍你关心的那几条是否已闭环。

- 你的工作流以**英文**为主；
- 你需要**加密存储**（它的真源是明文 md）；
- 你要**商用其评测数据集**。
