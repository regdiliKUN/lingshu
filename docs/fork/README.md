## 一句话摘要

**上游的算法层不慢，慢的全是系统调用。**

2000 个文件逐次 `open()+read` 需要 2751 ms；而一次 `os.scandir` 目录枚举把全部 size/mtime/属性免费带回，只需 3.9 ms——**52 倍**的差距。

所以十一轮优化的主线只有一条：**把「逐文件系统调用」换成「一次目录枚举 + 一次落盘快照」**，并且全程保持**检索结果逐位不变**。

## 三个最值得读的发现

### 1. R9：优化引入的真 bug

`consolidate` 一类写方走的是**直写文件 + `rebuild_index()`**，**不经过脏标记**，因此推不动 `write_gen`。而 R4 让扫描从 TTL 目录表取盘上身份——表没失效、`write_gen` 没动，于是扫描拿到的是**写之前的旧 `(size, mtime_ns)`**，恰好与旁路缓存里的旧条目「全等」⇒ **刚写下的新正文被旧正文顶掉**。

修法：新增 `_iter_md_files()` 自枚举，**身份与名字从同一次枚举取出**（遍历序与 `os.walk(topdown=True, followlinks=False)` 逐位一致）。

### 2. R10：生产路径的「读两遍」

类继承链是 `MdCG` → `MdCGOS` → `MdCGSecure`（**不是**直觉的 `MdCG → MdCGSecure → MdCGOS`）。而 `mcp_server.py` 构造的正是 `MdCGSecure`——**它才是生产路径**。它的 `_scan_nodes` 覆写了基类，在 `super()` 之后**逐节点再读一遍**，为的是取 `role` / `sensitivity` / `writer` 等字段。于是**真冷启动 = 2N 次 `open`**。

第一版修法是让读路径也认「本会话刚读到的正文」——**实测有效，但已回退**：它破坏了 `test_c3` 的 fail-closed 语义（扫描期读到的节点被外部锁住后，本该「读不到就不给」，却从会话快照里被供出）。**红线：「少读一次」不能越过「读不到就不给」。**

最终改在**扫描面**传递 frontmatter，读路径一个字都没动。

### 3. R11：被掩盖 9 轮的接线缺陷

`direct_read` 是治理面「写前重查 / 回滚比对」的**唯一真源**（六处读-改-写全靠它）。但它**实际没有**穿透旁路缓存——会读到装载时的旧正文做读-改-写，**静默覆盖**另一实例刚落盘的修正。

根因是 R2 的一处**死代码**：我在 `readcache.install()` 里追加了第二个 `if cg._read_uncached is None:` 分支，而文件里**原本已有一个**同名块 ⇒ 补丁从未生效。该测试的现场里 `_nodecache.json` 恰好不存在，`_sidecar_map()` 为空 ⇒ 缺陷被掩盖了整整 9 轮。

### 诚实边界（必须知道）

1. **规模**：所有读数基于**合成 2000 节点库**。万级 / 十万级规模**未实测**，收益外推需谨慎。
2. **噪声**：本机墙钟噪声 ±15~30%（Windows 实时防护对 `open` 的拦截开销波动），故报告以**系统调用计数**为主证、墙钟取 min-of-N 为辅证。
3. **新鲜度窗口**：读路径存在 ≤1 s 的窗口（`MDCG_DIRSCAN_TTL`，默认 1.0 s）——「进程内 + 外部改写 + 尚未读过的节点」最多 1 s 不可见。扫描路径**已无此窗口**。可用 `=0` 完全退回基线口径。
4. **落盘时机**：`_nodecache.json` 只在 `close()` 时落盘；强杀进程不落盘，退化为下次冷启动。
5. **基线时效**：本衍生版基线为上游 `958097d`，**不包含此后上游的新提交**。
6. **测试套件非幂等**：上游 `test_p28_refcheck` 使用固定夹具路径且默认不清空，一次中断的跑会把下一轮打红（与本衍生版改动无关的既有问题）。
7. **发布后由 CI 发现 1 项本衍生版引入的缺陷（已修）**：本次优化新增的 4 个环境变量
   （`MDCG_DIRSCAN` / `MDCG_DIRSCAN_TTL` / `MDCG_NODE_SIDECAR` / `MDCG_SCAN_WORKERS`）
   **未进配置登记面**，导致 `scripts.test_check_config_env_registry` 的反向对账判据 C1 转红。
   根因是优化期间**只跑了 `md_cg` 组套件（327 目标），漏跑 `scripts` 组（41 目标）**——
   而这条守卫恰好住在 `scripts/` 组里。已按上游 issue #120 的补登记先例补齐
   （登记面 721 → 725，C1 缺口 4 → 0，该守卫 20/20 通过）。
   **如实记录而非隐藏**：红基线可见才有自愈闭环，这也是该仓给 `python-tests` 刻意
   不加 `paths` 过滤的原因。
