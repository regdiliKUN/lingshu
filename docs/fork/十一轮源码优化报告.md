## 0. 结论摘要

**主证 = 系统调用计数**（不受本机墙钟噪声影响），**辅证 = min-of-N 墙钟**
（同一次会话内、串行测得，基线/优化版可比）：

| 关键读数（2000 节点库，min-of-N，同会话串行） | HEAD 原始 | 十一轮后 | 提升 |
|---|---|---|---|
| **首次运行冷启动**（无快照无缓存） | 1681.4 ms | **537.1 ms** | **3.1×** |
| **快照丢失后恢复装载** | 1618.8 ms | **73.1 ms** | **22.1×** |
| **热启动后首次检索** | 878.0 ms | **123.1 ms** | **7.1×** |
| **路径解析段**（全库 `_node_disk_path`） | 169.8 ms | **6.1 ms** | **28×** |
| **全量重建索引** `rebuild_index` | 1594.8 ms | **79.7 ms** | **20×** |
| 首次检索的 `.md` open 次数 | 2000 | **0** | 归零 |
| 恢复装载的 `.md` open 次数 | 2000 | **0** | 归零 |
| 路径解析的 `realpath` 次数 | 2000 | **3** | 归零 |
| 热启动 / 稳态检索 / 单节点读 | 20.5 / 17.3 / 0.1 ms | 21.9 / 19.6 / 0.2 ms | 持平（±15% 本机噪声） |

**生产类 `MdCGSecure` 专表**（`mcp_server.py:4536` 用的就是它；1000 节点）：

| 场景 | HEAD 原始 | 十一轮后 | 提升 |
|---|---|---|---|
| **真冷启动** | 1293.1 ms / **2000 open** | **228.4 ms / 1000 open** | **5.7× / open 减半** |
| **快照丢失恢复** | 2464.3 ms / **4000 open** | **106.8 ms / 0 open** | **23× / open 归零** |

> 「2000 open」不是笔误：`MdCGSecure._scan_nodes` 覆写了基类，在 `super()`
> 之后会**逐节点再读一遍**。这条被 R10 消掉（见 §2 第 10 轮）。

**一句话结论**：这套系统的算法层并不慢——**慢的全是系统调用**。2000 节点库里
`open()+read` 每文件 1.31 ms、`os.stat` 0.06 ms、`os.path.realpath` 0.14 ms，
而 md_cg 自身的解析+打分只占约 0.35 s。十一轮优化的主线因此只有一条：
**把「逐文件系统调用」换成「一次目录枚举 + 一次落盘快照」**，并且全程保持
**检索结果逐位不变**（见 §2.9 等价性对拍）。

后三轮不是「加功能」，而是**把「快」换回「对」**，且都产出了真实缺陷：

- **R9**：修 2 个由优化引入的真实正确性/契约缺陷 + 1 个自己的纪律违规，
  并识别出 1 条与改动无关的陈旧态假红；
- **R10**：发现生产类 `MdCGSecure` **真冷启动读两遍**（2N 次 open）并归零；
- **R11**：发现 R2 埋下的**死代码**——`direct_read` 其实**没有**穿透旁路缓存，
  治理面「写前重查」会拿到陈旧正文 ⇒ 六处 RMW 读点的安全保证被削弱。
  **这条缺陷被掩盖了 9 轮**，靠 R10 的试改引爆才现形。

## 1. 源码逐层拆解

### 1.1 分层地图（仓库级）

```

├── md_cg/        ← 记忆本体（479 个顶层 .py，192,132 行）★ 本次全部工作在此
│   ├── mdcg.py       (5,308 → **5,924** 行)  MdCG / MdCGSecure —— 索引、读写、资格判定
│   ├── mdcos.py      (6,042 → **6,113** 行)  MdCGOS —— 白箱操作系统面（检索/审计/回收站/会话）
│   ├── mcp_server.py (4,687 行)   stdio MCP 服务器（工具面 + 分派）
│   ├── readcache.py  (291 → **302** 行)   进程内读缓存（脏集精确失效）
│   ├── nodefile.py   (873 行)     frontmatter 序列化/解析单点
│   ├── fsutil.py     (824 行)     原子写/文件锁/分片日志/瞬时读失败判别
│   └── … 471 个功能模块 + 337 个 test_*.py

```

关键事实：**`md_cg/` 对其余四层零依赖**——记忆层可独立部署，这是它作为
「记忆系统」而非「AGI 框架」的边界所在。

### 1.2 三个类族的职责切分

**继承链（核实后的实际形态——与直觉相反，务必按此读）**：

```
MdCG            (mdcg.py:1801)  认知图基类：索引、节点读写、资格判定、检索
  └─ MdCGOS     (mdcos.py:665)  = MdCG + 记忆 OS 七项能力（检索/审计/回收站/会话/治理）
       └─ MdCGSecure (mdcos.py:5255)  = MdCGOS + 租户/密级/敏感度（principal）
```

**不是** `MdCG → MdCGSecure → MdCGOS`。这一点很关键：
`mcp_server.py:4536` 构造的正是 `MdCGSecure(root, principal=principal, autoflush=1)`
——**生产路径走的是最外层那个子类**，所以它的行为特征（见下）直接决定用户体感。

| 类 | 文件 | 定位 | 关键方法 |
|---|---|---|---|
| `MdCG` | mdcg.py | 认知图基类 | `_load_index` / `_scan_nodes` / `_node_entry` / `_read_status` / `search` / `add` |
| `MdCGOS` | mdcos.py | + 记忆 OS 七项能力（RRF 检索、审计、回收站、会话、治理） | `search_rrf` / `recall` / `forget` / `restore` / `verify` |
| `MdCGSecure` | mdcos.py | + 租户 × 密级（clearance）× 敏感度，读写/管理三重隔离 | `_scan_nodes`（**覆写**）/ `add` / `propose` / `review_*` / `_attributed_session` |

> **`MdCGSecure._scan_nodes` 是覆写，且它会「读两遍」**：
> `nodes = super()._scan_nodes()` 之后逐节点再 `self._read(e)` 一遍，
> 为的是把 `role` / `sensitivity` / `writer` / `session` / `content_kind`
> 写回索引条目。生产路径（MCP）走的正是这个类，所以：
> **真冷启动 = 2N 次 `open`**（1000 节点实测 2000 次）。这是本次优化的
> 第 10 轮所针对的目标（见 §2 第 10 轮）。

真源纪律：**盘面 `.md` 是唯一真源**，`_index.json`、分片日志、读缓存、
第 3 层结构索引**全部是派生物**，任何一层损坏都不得污染真源。

### 1.3 读路径执行流（改造前）

```
MdCGSecure.__init__(root, principal)          ← 生产路径（mcp_server:4536）
  └─ MdCGOS.__init__ → MdCG.__init__
       ├─ _load_index()
       │    ├─ _index.json 存在且 schema 对？
       │    ├─ _dir_fingerprint() 匹配？          ← 只 walk 目录 + 每目录 1 次 stat
       │    └─ 不匹配/缺失 → self._scan_nodes()
       │         └─ MdCGSecure._scan_nodes()      ← 覆写：super() 之后再逐节点 _read
       │              ├─ MdCG._scan_nodes()       ← ★ 逐文件 open+read+parse（N 次 open）
       │              └─ for nid, e in nodes:     ← ★★ **再 open 全库一遍**（N 次）
       │                   self._read(e)            为了取 role/sensitivity/writer/session
       └─ readcache.install(self)                 ← 进程内缓存装配（默认开）
                    ↓
search_rrf(query)
  ├─ _maybe_reload_index()                        ← stat 签名比对
  ├─ hotcache 查询结果缓存（默认关）
  └─ _lexical → _read_many(entries)
       └─ _read(entry) → _read_status(entry)
            ├─ _node_disk_path(entry)             ← ★ 每节点 1 次 realpath
            └─ open(p) + nodefile.loads()         ← ★ 每节点 1 次 open
```

四处 `★` 就是全部瓶颈。两点关键：

1. **`★★` 是最容易被忽略的一处**：`MdCGSecure._scan_nodes` 的覆写让
   **真冷启动变成 2N 次 `open`**，而它是生产路径。R2/R4 的旁路缓存把它压到
   0（热恢复腿），R10 又把「真冷启动」从 2N 压到 N（见 §2 第 10 轮）。
2. **`_read_many` 在首次检索时对全库每个节点调用 `_read`**，与查询词无关——
   这是「候选面 O(N)」的设计后果，也是「热启动后首次检索要 0.9 s」的根因。

### 1.4 写路径执行流

```
add(node_id, content, …)
  ├─ node_id 白名单闸（_NODE_ID_RE + '..' + realpath 越界）
  ├─ protect.guard_write（不可遗忘保护）
  ├─ _write_node() → atomic_write 落盘 .md（真源）
  └─ _stage(nid, entry)  → 内存索引 + _dirty[nid]（脏集代际 +1）
                                  ↓ flush()
                             ShardedLog.append({"id", "e"})   ← append-only 分片日志
                                  ↓ close()
                             compact_index() → 重写 _index.json + 清分片
```

**写路径是「零 LLM」的**：全程确定性规则，实测 0.011–0.019 s/次。
这是该项目相对「抽取式记忆」（用 LLM 抽取再入库，300–660 s）最硬的优势。

### 1.5 资格判定与三闸

```
写入 → audit 闸 → consistency 闸 → gated 闸（三问/四态）
                                        ↓
                        ACCEPT / REJECT / DEFER / BLINDSPOT
                                        ↓
                        仅 ACCEPT 落盘；committed 字段才是真相（不是 ok:true）
```

`BLINDSPOT`（标记「我不知道」而非猜）是这套设计里最有价值的一态——
它把「不确定」变成一等公民，而不是伪装成确定。

### 1.6 测量基线（先量化，再动手）

**OS 层理论下限**（2000 文件，本机）：

| 操作 | 总耗时 | 单次 |
|---|---|---|
| `os.stat` ×2000 | 123.1 ms | 0.061 ms |
| `open(rb)+read` ×2000 | 2751.5 ms | 1.376 ms |
| `open(r,utf-8)+read` ×2000 | 2611.8 ms | 1.306 ms |
| `os.path.realpath` ×2000 | 366.7 ms | 0.183 ms |
| `os.path.islink` ×2000 | 93.4 ms | 0.047 ms |
| **`os.scandir` 取全量 is_symlink+stat ×2000** | **3.9 ms** | **0.002 ms** |

`open()` 比 `stat()` 贵 **22×**，而 `scandir` 一次目录枚举就能免费拿回

即：**代码只占 10%，82% 是等操作系统**。

## 2. 十一轮优化（R1–R8 性能 / R9 回归修复 / R10–R11 深挖）

> **读法说明（重要）**：各轮的「前 / 后」是在**该轮所在会话**内测得的，
> 而本机墙钟会随会话波动（Windows 实时防护对 `open` 的拦截开销 ±15~30%）。
> 因此：
> - **跨轮可比**的是同一张表内的「前后比」，以及**系统调用计数**（`open` /
>   `stat` / `realpath` 次数）——后者是确定的整数，不受噪声影响；
> - **跨会话不可比**绝对值。§0 的对照表是**最后一次同会话、串行**测得的
>   基线/优化版读数，是本文档的权威读数；§2 各轮表只用于展示**该轮增量**。

### 第 1 轮：目录级 realpath（消除 O(N) 符号链接解析）

**目标**：`_node_disk_path` 每节点一次 `os.path.realpath`，而 realpath 在 Windows
落到 `nt._getfinalpathname`（每次 2 次句柄查询）。

**改动**（`mdcg.py`）：
- `__init__` 新增 `_dir_real_cache`；
- `_node_disk_path` 改为「**目录 realpath 一次 + 末段拼接**」；
- 末段单独判链接（`islink`，lstat，比 realpath 便宜 4×），命中即回落整路径 realpath；
- `_maybe_reload_index` 同款清空。

**语义保持**：realpath 会解析路径**每一段**（含末段）的符号链接。拆开后末段
可能被绕过，故用 `islink` 单独补回——**不是放宽校验**。返回字符串与旧实现逐位一致。

**效果**：

| 指标 | 前 | 后 |
|---|---|---|
| `pathpass_realpath` 调用次数 | 2000 | **3** |
| `pathpass_ms` | 401.2 | **88.6**（−78%） |
| `first_search_realpath` | 2001 | **4** |

### 第 2 轮：正文旁路缓存（首次检索零 open）

**目标**：热启动后首次检索仍要 2000 次 `open`（约 1.2–1.9 s），而
`readcache` 是**纯进程内内存缓存、不落盘**，每次新进程都要重新付这笔钱。

**改动**（R2 时落在 `readcache.py`，**R9 已迁至 `mdcg.py`**——原因见 §2 第 9 轮；
本文档统一按最终位置描述）：新增 `_load_sidecar` / `_save_sidecar`（`mdcg.py`）
与 `_read_status` 拆分、`_sidecar_*` 三方法：
- 新增派生物 `<root>/_nodecache.json`，每节点存 `[size, mtime_ns, fm, content]`；
- `_read_status` 先试旁路缓存（**命中即完全不 open**），未命中回落
  `_read_from_disk` 真读盘；
- 登记侧的 stat 取自**同一读句柄的 `os.fstat`** ——与正文严格同源，杜绝
  「读完文件再 stat 路径」把新 stat 与旧正文配对落盘的竞态；
- 装载侧**只做类型清洗、不做 stat**（校验延迟到逐条命中），于是 2.5 MB 的
  缓存不会给热启动加钱；
- 落盘侧按当前索引**剪枝**（已删节点条目不留），单节点正文上限 64 KiB。

**关键设计选择——为什么放独立文件而不塞进 `_index.json`**：
`test_p2_six_elements.py` 要求「两次 rebuild 的 `_index.json` **字节相同**」，
而 size/mtime 每次都变，塞进去必然破坏该不变量。

**为什么治理面直读要穿透它**：`readcache.direct_read`（写前重查/回滚比对）
契约要求「读盘上真值」，故改指 `_read_from_disk`（**旁路缓存的穿透落点**）。
为此把原 `_read_status` 拆成两半——拆出的方法名刻意避开 `_read_status` 前缀，
以免触发 `test_c3` 的守卫 `count("def _read_status") == 1`（**未改任何测试**）。

**效果**：

| 指标 | 前 | 后 |
|---|---|---|
| `first_search_open_md` | 2000 | **0** |
| `first_search_ms` | 1900± | **279.7** |
| 旁路缓存体积（2000 节点） | — | 991.6 KB |

**诚实边界**：判据是 `(size, mtime_ns)` 全等，与 make/git 同族。外部改写且
**字节数不变、mtime 又被回拨**的场景不可见（需显式篡改，如 `touch -r`）。
相比既有 `_dir_fingerprint`（只看目录 mtime、**完全不看**同目录内容改写），
本判据严格更强。`MDCG_NODE_SIDECAR=0` 可关，`MDCG_READ_CACHE=0` 同样关。

### 第 3 轮：目录条目表（消除逐节点 stat / islink）

**目标**：R2 后首次检索剩 602 ms，其中 `nt._path_islink` 2000 次 **177 ms**
（29%）+ `nt.stat` 2002 次 **163 ms**（27%）= 56%，全是 R1/R2 保留的逐路径调用。

**改动**（`mdcg.py`）：
- 新增 `_dir_entries(rel_dir)`：一次 `os.scandir` 取全目录
  `(table: 文件名→(size,mtime_ns), links: 符号链接集合)`；
- `_dir_islink` / `_dir_stat` 两个消费面，**拿不到就逐路径回落**（宁慢不误判）；
- `_node_disk_path` 的末段判链接改走 `_dir_islink`；
- `_sidecar_hit` 的盘上身份改走 `_dir_stat`。

> **消费面边界（第 9 轮订正）**：目录条目表**只服务读路径**（`_sidecar_hit`、
> `_node_disk_path`）。**扫描路径 `_scan_nodes` 一律不用它**——扫描自己就在
> 枚举目录，身份读数必须来自那次枚举本身。详见 §2 第 9 轮。

**失效口径**：按 `_dirty.write_gen` 键控（任何写入即整表作废，全库重建仅 4 ms）
**外加时间上限** `MDCG_DIRSCAN_TTL`（默认 1.0 s）。

**为什么要 TTL**：目录表若长期有效，「进程内 + 外部改写 + 尚未读过的节点」
这一窗口会从 0 扩大到进程生命周期。加 TTL 后窗口收敛到 ≤1 s，**严格强于**
既有 `readcache`（后者一旦读过就在进程内长期生效）。设 0 即完全退回基线口径。

**效果**：

| 指标 | 前 | 后 |
|---|---|---|
| `first_search_ms` | 602.5 | **115.4** |
| `pathpass_ms` | 200.4 | **5.8**（−97%） |
| 每 2000 文件的 stat+islink 成本 | 203 ms | **3.9 ms**（52×） |

### 第 4 轮：冷启动也免 open（旁路缓存反哺索引扫描）

**目标**：`_scan_nodes`（全库扫描）仍逐文件 `open`——它是**快照丢失/损坏、
指纹失配、外部增删文件**三条真实故障腿的必经之路。

**改动**（`mdcg.py`）：
- `_scan_nodes` 接 `_sidecar_map()`；对每个文件先问**本次枚举自带的**
  `(size, mtime_ns)`（`_iter_md_files`，见 §2 第 9 轮），与旁路缓存全等即
  **直接复用 `fm`/`content`，不开文件**；
- 未命中回落原 `open` 路径；
- 顺手删掉循环里重复的 `os.path.relpath`（2000 节点里 0.13 s 的纯冗余）。

**效果**：

| 指标 | 前 | 后 |
|---|---|---|
| `recover_init_ms`（快照丢失后恢复） | 2032.5 | **80.9**（25×） |
| `recover_open_md` | 2000 | **0** |
| `rebuild_ms` | 2042.3 | **83.2**（24.6×） |

### 第 5 轮：trash 路径穿越闸（issue #172）

**目标**：`restore()` 与 `_forget_apply()` 各自 `os.path.join(trash_dir, f"{node_id}.md")`。

**实际影响面（核实后的诚实结论）**：
- `restore(node_id)` 的 `node_id` 是**调用方可控入参**（MCP 工具面直达）。
  修前 `../../x` / 绝对路径能把 `open(src)` 引到库外——**任意 `.md` 文件读取**，
  并把内容喂进节点解析面；而 `add` 的白名单在 40 行之后才拒，于是契约里承诺的
  「结构化失败」变成**未捕获 `ValueError`**。
- `os.remove(src)` 实际**不可达**（`add` 先抛），故**不是**任意删除——但它
  「靠 40 行外的另一个函数兜底」本身是隐患：一旦校验被放宽或次序调整即成漏洞。
- `_forget_apply` 的 `dst` 更危险：`os.replace(src, dst)` 的**目标**越界即
  **任意路径覆写**；其 `src` 也是裸拼，绕过读面 P2-20 闸。

**改动**：
- 新增 `MdCGOS._trash_path(node_id)` 单点，两道判据：① 字面闸——**复用写面
  `_NODE_ID_RE`**（不另写第二份白名单）+ `..` + 长度 + `basename(nid)==nid`
  + 驱动器号/绝对路径；② realpath 闸——解析结果必须落在 `trash_dir` 内
  （兜住符号链接/junction）。
- `restore` 改为先过闸再落地，非法即 `{"ok": false, "error": "bad_node_id"}`、
  **零 IO**；
- `_forget_apply` 的 `src` 改走 `_node_disk_path`（读面同一个 P2-20 单点），
  `dst` 改走 `_trash_path`。

**效果**：`verify_r5r6.py` **35/35 PASS**——5 类穿越串全部结构化拒绝、诱饵
文件未被读取、正常软删/恢复路径不误伤。

### 第 6 轮：证伪硬删改可恢复摘除（issue #144）

**目标**：`verify(verdict="falsified")` 走 `os.remove(os.path.join(self.root, node["path"]))`

### 第 9 轮：回归修复（把「快」换回「对」）

**目标**：R1–R8 完成后跑全量套件，出现 **4 个新失败**。这一轮不加任何新特性，

#### 9.1 `test_p6_consolidate` · `has_neg_conditions 已同步 = False`

**根因（真 bug，我的 R4 引入）**：`consolidate` 一类写方走的是
`cg._write_node(...)` **直写文件 + `cg.rebuild_index()`** 收尾——它**不经**
`_dirty`，因此推不动 `_dirty.write_gen`。而 R4 让 `_scan_nodes` 用
`_dir_stat`（＝ `_dir_entries` 的 TTL 表）取盘上身份，那张表按
`write_gen + TTL(默认 1s)` 失效；直写既不动 `write_gen`、TTL 又没过期，
于是扫描拿到的是**写之前的旧 `(size, mtime_ns)`**，恰好与旁路缓存里的旧条目
「全等」⇒ **刚写下的新正文被旧正文顶掉**，重建出的索引仍是旧值。

这不是「测试太刁」：`rebuild_index()` 的语义就是「以**当前盘面**重建索引」，
拿到旧 stat 就是错的。

**改动**：新增 `MdCG._iter_md_files()`——用 `os.scandir` **递归自枚举**，
`entry.stat()` 在 Windows 上零 syscall（`FindFirstFile/FindNextFile` 已带回
size/mtime），于是「扫描用的名字」与「扫描用的身份」**同源同代**，不可能
出现「枚举是新的、stat 是旧的」。`_scan_nodes` 改用它，第三遍登记旁路缓存
也直接复用这份读数（顺带**省掉每文件一次 `_dir_stat`**）。

**遍历序等价性**：与 `os.walk(topdown=True, followlinks=False)` **逐位一致**
（同目录内按 `os.scandir` 原始序、子目录 `reversed` 压栈弹出），故 dict
「后到覆盖」语义（重复 nid 谁胜出）与改动前完全相同。定向验证
`verify_walk_equiv.py`：文件集合一致 ✅、**顺序逐位一致** ✅、含符号链接、
坏符号链接与符号链接**目录** ✅（坏链接身份读数为 None 是预期——它随后真读
失败即跳过）。

**根因链实证**（`verify_p6_rootcause.py`，9/9 PASS）——不只推理，逐环钉住：

```
预热读数 == 旁路缓存条目                      PASS
① 直写后 write_gen **不变**                   PASS   （表不会因此失效）
② 表返回**写之前**的 (size, mtime)            PASS
     表读数: (439, 1791842808420945700)
     盘上真值: (500, 1791842808517946200)   ← 文件确实变了，表没跟上
③ 陈旧读数与旁路缓存条目**全等**              PASS   （旧正文会被判成「没变」）
④ 旧实现**会命中**陈旧缓存                    PASS
④' 旧实现拿到的正文是**旧**的（不含新声明）   PASS
⑤ 新实现 rebuild 后取到**新**正文             PASS   （修复生效）
```

#### 9.2 `test_c3_transient_read_negative` · G5c「缓存层不重判」

### 第 10 轮：生产类 `MdCGSecure` 的「读两遍」归零

**发现路径**：订正 §1.2 的类继承事实时发现的——不是猜的，是量出来的。

`mcp_server.py:4536` 构造的是 **`MdCGSecure`**（生产路径）。而
`MdCGSecure._scan_nodes` 覆写了基类：

```python
def _scan_nodes(self):
    nodes = super()._scan_nodes()          # 读全库 N 次
    for nid, e in nodes.items():
        fm, _c = self._read(e)             # ← 再读全库 N 次
        if fm:
            e["role"] = ...; e["sensitivity"] = ...; e["writer"] = ...
            e["session"] = ...; e["content_kind"] = ...
    return nodes
```

它要的是 `role`/`sensitivity`/`writer`/`session`/`content_kind`——而
`_node_entry` 的**固定键集**里**没有** `sensitivity` 与 `writer`（`role` /
`session` / `content_kind` 本来就有，属重复取），于是它**把每个文件重新读一遍**。
**真冷启动 ⇒ 2N 次 `open`**（1000 节点实测 2000 次，基线冷启动 1293 ms）。

**为什么 R2/R4 没顺手修掉**：旁路缓存让第二遍在**热恢复腿**上命中
（`_sidecar_map()` 里已有），于是「快照丢失」这一腿从 4000 次 open 归零；
但**真冷启动**时旁路缓存还不存在，第二遍无处可命中——那 2N 仍然是 2N。

#### 10.1 第一版做法（**已回退**，如实记录）

最省事的改法是让读路径也认「本会话刚读到的正文」：把 `_sidecar_hit` 的取值
改成 `_sidecar_staged` 优先于 `_node_sidecar`。**实测有效**（冷启动 2000→1000
次 open、560.6→236.7 ms），但**打红了 `test_c3_transient_read_negative`
的 5 项断言**：

```
FAIL G1b 读失败 fail-closed：不可读节点不参与检索（不泄漏半读内容）
FAIL G1c 【②】负结果**不入缓存**：该 path 无缓存条目
FAIL G1d 【③】不得静默：瞬时读失败计入模块级计数
FAIL G1e 【②代价面】重试有界（稳态一次查询）
FAIL G1f 【①】三态标签实测：瞬时读失败 → 第三元素 = READ_FAIL_TRANSIENT
```

现场：节点在扫描时读到了，之后被**外部独占锁**锁住——本该「不可读 ⇒ 不参与
检索」，却会从本会话快照里被端出来。**这是红线，不能越**：
**「少读一次」不能越过「读不到就不给」**（C-3 的 fail-closed 语义）。
⇒ **回退该改动**。

#### 10.2 最终做法：把 fm 沿**扫描**这条线传下去

不动读路径，改在**扫描面**消掉第二遍。基类新增一个类级开关与一份留底：

```python
class MdCG:
    _SCAN_KEEP_FM = False        # 只有真正需要的子类才留（普通 MdCG/MdCGOS 不占内存）

    def _scan_nodes(self):
        ...
        _keep_fm = getattr(self, "_SCAN_KEEP_FM", False)
        _scan_fm = {}
        if _keep_fm:
            self._scan_fm = _scan_fm          # 每次全量扫描都重建，不留残影
        ...
        # 第三遍：条目构造成功后
            if _keep_fm:
                _scan_fm[nid] = fm            # 刚解析出的 fm，就地留一份
```

```python
class MdCGSecure(MdCGOS):
    _SCAN_KEEP_FM = True

    def _scan_nodes(self):
        nodes = super()._scan_nodes()
        fms = getattr(self, "_scan_fm", None) or {}
        for nid, e in nodes.items():
            fm = fms.get(nid)
            if fm is None:                    # 留底缺该 nid 才回落真读
                fm, _c = self._read(e)
            if fm:
                e["role"] = ...; e["sensitivity"] = ...; ...
        self._scan_fm = None                  # 用完即弃，不常驻
        return nodes
```

**为什么这个做法是对的**：那批字段**本来就在基类刚解析出的 `fm` 里**，
只是被 `_node_entry` 的固定键集丢掉了。把 fm 沿着**同一次扫描**传下去，
第二遍**零 open**；而**读路径一个字都没动**——c3 的 fail-closed 红线、
`direct_read` 的盘上真值语义、旁路缓存的接纳口径全部保持原样。

**效果**（`probe_secure.py`，`MdCGSecure`，1000 节点，min-of-3，同会话串行）：

| 场景 | 基线 HEAD | R9 | **R10（最终）** | 相对基线 |
|---|---|---|---|---|
| **真冷启动**（无快照无缓存） | 1293.1 ms / **2000 open** | 560.6 ms / 2000 open | **228.4 ms / 1000 open** | **5.7× 时间 / open 减半** |
| **快照丢失恢复**（留旁路缓存） | 2464.3 ms / **4000 open** | 138.3 ms / 0 open | **106.8 ms / 0 open** | **23× 时间 / open 归零** |

> R9 与 R10 的冷启动之差（560.6 → 228.4 ms）正是**第二遍全库 open** 的成本：
> 1000 次 open ≈ 330 ms，与 R1 测得的「每文件 1.31 ms、线程池摊薄后 ~0.3 ms」
> 完全对得上。

## 3. 首次使用全流程与引导机制

> **先纠正一个前提**：dsh-memory **不是一个网站**，没有「打开网页 → 注册 → 点按钮」
> 这条路径。它的交付形态是 **Python 库 + stdio MCP 服务器**，用户侧只有三种入口：
> ① `git clone` 仓库当库用；② 作为 MCP 服务器挂进宿主（Claude Desktop / Cursor /
> DSH 等）；③ 通过 `@deepseek-ai/dsh` 生态间接使用。因此下文的「首次访问」= 从
> **拿到仓库** 到 **第一次检索有结果**，这也是「核心功能可用」的真实定义。
> 这一段的所有读数都来自 §2 的同一套探针，不是估算。

### 3.1 全流程映射（首次访问 → 核心功能可用）

| 阶段 | 用户动作 | 系统实际发生什么 | 原体验痛点 | 本轮处置 |
|---|---|---|---|---|
| **① 拿到仓库** | `git clone` | 94 MB / 479 个 `.py` | — | — |
| **② 选路径** | 读 README | 仓库含 5 个子系统，**只有 `md_cg/` 是记忆本体** | 极易误以为要装 rust/swarm/compiler/hive | §3.2 引导第 1 条 |

## 5. 剩余风险与未做项（诚实清单）

1. **`_dir_fingerprint` 只看目录 mtime**，同目录**内容级改写**不触发重扫。
   这是既有设计（代码注释已诚实声明），R4 让这条路径更快，但没有让它更准。
   外部直接改写 `.md` 仍属「非合作写者协议」。
2. **R3 的 1 s 窗口只作用于读路径**（第 9 轮订正后）：`_sidecar_hit` /
   `_node_disk_path` 经 `_dir_entries` 的 TTL 表判盘上身份，故「进程内 +
   外部改写 + 尚未读过的节点」最多 1 s 不可见。**扫描路径（`_scan_nodes` /
   `rebuild_index`）已无此窗口**——它改用 `_iter_md_files` 的自枚举读数，
   身份与名字同源同代（这正是 R9 修掉的 `test_p6_consolidate` 缺陷）。
   可用 `MDCG_DIRSCAN_TTL=0` 把读路径也完全退回基线口径。
3. **旁路缓存不是第二真源，但也不是零成本**：2000 节点约 1 MB，与节点正文
   总量同阶。巨型库需关注盘占用（已有 64 MiB 硬上限）。
4. **`_nodecache.json` 只在 `close()` 落盘**。MCP 服务器优雅退出会调 `close()`
   （已核实 `mcp_server.py:4680`），但强杀进程不落盘——退化为下次冷启动。
   可考虑加「每 N 条新增即增量落盘」的 debounce，本轮未做。
5. **2000 节点规模**。所有读数都基于合成库；万级/十万级未实测，
   并发读盘与目录表的收益外推需谨慎。
6. **本机墙钟噪声约 ±15~30%**（Windows 实时防护对 `open` 的拦截开销波动大），
   故本报告把**系统调用计数**作为主证、墙钟只作辅证并取 min-of-N。
7. **`_iter_md_files` 与 `os.walk` 是「手工镜像」关系**：R9 用它替掉
   `_scan_nodes` 里的 `os.walk`，并已用 `verify_walk_equiv.py` 钉住
   「文件集合 + 遍历序逐位一致」。但这是一条**需要人工维护的不变量**——
   将来若上游改了 `os.walk` 的语义（或有人把某处改回 `os.walk`），
   要重跑该脚本。更稳的做法是把它升格为套件内守卫，本轮未做（不改测试）。
8. **`test_p28_refcheck` 本身不幂等**（与本轮改动无关的既有问题）：
   它的夹具根 `<repo>/_md_cg_p28` 是固定路径且 `reset_root` 默认不清空，
   而 `_refindex.json` 的水位键是源文件**绝对路径** ⇒ 一次崩溃/中断的跑会
   把下一轮打红，且报错指向「水位 files」极具误导性。我把陈旧夹具移开即恢复
   绿色。建议上游把该夹具改为 `mkdtemp` 或 `reset_root(clean=True)`。
9. **本机预存测试失败**与本轮改动无关（基线同样失败），未逐一排查；
   且**同一份 HEAD 两次跑的失败集合会漂移**（时序/并发/超时敏感），
   故回归判定以「**新失败集合**」为准，而非失败总数。最终读数见 §2.9。
10. **本机 501 个残留测试临时目录**（`%TEMP%\mdcg_*` / `lingshu_*`）未清理——
    它们不参与判据，但会占用磁盘。清理动作留给使用者（我不对个人/临时目录
    做批量删除）。
